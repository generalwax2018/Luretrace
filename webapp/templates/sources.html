Ingest sources

Where the links come from. Configure connectors in your deployment; the console shows the verdicts regardless of source.

{{ icon('inbox',18) }} Mimecast

Pulls clicked/scanned URL logs from Mimecast API 2.0 (OAuth2) and queues their targets. The gateway's own scan result is carried through, so a link Mimecast passed that luretrace fails is easy to spot.

connector: mimecast · POST /api/ttp/url/get-logs

{{ icon('grid',18) }} Data lake / SIEM

Runs a query against an OAuth2-protected endpoint (Snowflake, Databricks SQL, Azure Data Explorer, Elastic, or a custom gateway) and maps result fields to URLs. Vendor-neutral: configure the query and a field map, no code.

connector: datalake · OAuth2 client-credentials

How a link becomes a verdict

  1. Ingest — a connector yields the URL (plus recipient, message id, and the gateway's own verdict).
  2. Unwrap — Safe Links / Proofpoint / Mimecast rewrites are decoded to the real destination.
  3. Detonate — the link is opened in an isolated browser and the lure chain is followed to its end.
  4. Score — a branded sign-in page on a domain the brand doesn't own is the headline signal.
  5. Review — passed links are logged; failed links land in the queue with full forensics.

Connectors authenticate with OAuth2 client-credentials and are configured in the deployment, not here. See webapp/ingest.py and docs/deployment.md.
